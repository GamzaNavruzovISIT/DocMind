# DocMind — локальный ИИ-ассистент для документов

## Возможности

- **Чат с документом (RAG)** — вопросы к PDF/DOCX/TXT со ссылками на фрагменты-источники; клик по источнику прокручивает документ к нужному месту. Ответ стримится токенами.
- **OCR скан-копий** — PDF без текстового слоя и изображения (PNG/JPEG) распознаются локальным Tesseract (русский + английский). Никаких внешних сервисов.
- **Предпросмотр оригинала** — вкладка «Оригинал» показывает PDF постранично (pdf.js) и DOCX как документ, сущности подсвечиваются прямо в превью.
- **Подсветка сущностей** — в тексте документа автоматически подсвечиваются:
  ФИО, телефоны, e-mail, даты, адреса, организации, суммы, реквизиты (ИНН, паспорт, СНИЛС, ОГРН).
  Два уровня: быстрый regex-анализ (мгновенно) и глубокий ИИ-анализ (кнопка «Глубокий поиск сущностей»).
- **Свои сущности** — кнопка «Подсветить» в просмотрщике: введите слово, фразу или regex — все совпадения подчеркнутся. Можно сохранить как постоянный шаблон (управление — в «Настройках»).
- **Шаблоны извлечения** — создавайте свои шаблоны полей («Договор»: стороны, сумма, срок…),
  модель извлекает каждое поле и приводит цитату-подтверждение. Экспорт в CSV.
- **Экспорт и интеграции** — выгрузка данных документа (текст, сущности, извлечённые поля) в JSON одной кнопкой или отправкой POST на ваш сервер.
- **Настройки из интерфейса** — адрес и порт Ollama, модели, подключение к PostgreSQL, OCR, удалённый сервер, порт приложения — всё на странице «Настройки», без правки .env.
- **Библиотека документов** — загрузка drag-and-drop, статусы обработки, история чатов и извлечений.
- **Приватность** — документы не покидают машину: локальный Ollama и локальный PostgreSQL. Удалённая отправка — только по вашей кнопке на ваш сервер.

## Стек

| Слой | Технология |
|---|---|
| Фронтенд | React 19, TypeScript, Vite, Tailwind CSS, shadcn/ui |
| Бэкенд | Node.js, Hono, Server-Sent Events |
| LLM и эмбеддинги | Ollama (по умолчанию `qwen2.5:7b` + `nomic-embed-text`) |
| База данных | PostgreSQL (без расширений — эмбеддинги в JSONB, близость считается на сервере) |
| Парсинг | pdf-parse (PDF), mammoth (DOCX) |
| OCR | tesseract.js (WASM, сканы PDF и изображения) + pdf-to-img |

## Быстрый старт

### 1. Предварительные требования

- **Node.js 20+** — https://nodejs.org
- **PostgreSQL 14+** — https://www.postgresql.org/download/
- **Ollama** — https://ollama.com/download

### 2. Установите модели Ollama

```bash
ollama serve                # в отдельном терминале, если не запущен
ollama pull qwen2.5:7b      # чат-модель (хорошо понимает русский)
ollama pull nomic-embed-text # модель эмбеддингов для поиска
```

Можно выбрать другие модели — см. «Настройка» ниже.

### 3. Создайте базу данных

```bash
# Windows (cmd/PowerShell), Linux, macOS — одинаково, если psql в PATH:
psql -U postgres -c "CREATE DATABASE docmind;"
```

### 4. Настройте окружение

```bash
cp .env.example .env
# при необходимости поправьте DATABASE_URL (логин/пароль PostgreSQL)
```

### 5. Установите зависимости и подготовьте БД

```bash
npm install
npm run db:init
npm run dev:server # Открыв второй терминал
npm run dev
```

### 6. Запуск

**Режим разработки** (фронтенд на :3000 с hot-reload, API на :8787):

```bash
npm run dev
```

**Production-режим** (один сервер на :3000, отдаёт и интерфейс, и API):

```bash
npm run build
npm start
```

Откройте http://localhost:3000

## Настройка (.env и страница «Настройки»)

Всё нижеперечисленное можно менять прямо в интерфейсе (пункт меню «Настройки») —
значения сохраняются в `settings.json` и имеют приоритет над `.env`.

| Переменная | По умолчанию | Описание |
|---|---|---|
| `PORT` | `3000` | Порт production-сервера |
| `DATABASE_URL` | `postgres://postgres:postgres@localhost:5432/docmind` | Строка подключения к PostgreSQL |
| `OLLAMA_BASE_URL` | `http://localhost:11434` | Адрес Ollama |
| `OLLAMA_CHAT_MODEL` | `qwen2.5:7b` | Чат-модель (альтернативы: `llama3.1:8b`, `qwen2.5:14b`, `mistral`) |
| `OLLAMA_EMBED_MODEL` | `nomic-embed-text` | Модель эмбеддингов (альтернатива: `mxbai-embed-large`) |
| `OCR_ENABLED` | `true` | Распознавать сканы PDF и изображения |
| `OCR_LANGUAGE` | `rus+eng` | Языки Tesseract (`rus+eng`, `rus`, `eng`) |
| `OCR_MAX_PAGES` | `30` | Максимум страниц скана на документ |
| `REMOTE_EXPORT_URL` | — | URL для отправки извлечённых данных (кнопка «Отправить») |
| `REMOTE_EXPORT_TOKEN` | — | Bearer-токен для удалённого сервера |
| `UPLOADS_DIR` | `uploads` | Куда складываются оригиналы файлов |
| `NER_MAX_CHARS` | `60000` | Сколько текста максимум идёт в ИИ-анализ сущностей |

> Если поменяли `OLLAMA_CHAT_MODEL` / `OLLAMA_EMBED_MODEL` — не забудьте `ollama pull <модель>`.

## Как это устроено

```
Загрузка файла
     │
     ▼
Парсинг (pdf-parse / mammoth, сканы — через OCR) ──► полный текст ──► regex-NER (мгновенная подсветка)
     │
     ▼
Чанкование (~1400 символов, перекрытие 200)
     │
     ▼
Эмбеддинги в Ollama (nomic-embed-text) ──► PostgreSQL (JSONB)
     │
     ▼
Вопрос пользователя ──► эмбеддинг ──► top-5 фрагментов (косинусная близость)
     │
     ▼
Промпт с контекстом ──► qwen2.5 (стрим SSE) ──► ответ + ссылки на фрагменты
```

- `server/` — бэкенд (Hono): маршруты, конвейер обработки, NER, клиент Ollama
- `db/schema.sql` — схема PostgreSQL (создаётся автоматически при старте)
- `src/` — фронтенд (React): библиотека, рабочее место документа, шаблоны
- `contracts` не используются — API REST + SSE, типы клиента в `src/types/`

## Ограничения и заметки

- Скан-копии PDF распознаются OCR (Tesseract, локально). При первом распознавании
  скачиваются языковые данные (~10 МБ, нужен интернет один раз) — дальше всё офлайн.
  Качество зависит от качества скана; в превью скана подсветка не накладывается на картинку —
  смотрите вкладку «Текст».
- Подсветка сущностей во вкладке «Оригинал» работает в браузерах с CSS Custom Highlight API
  (Chrome/Edge 105+, Safari 17.2+, Firefox 140+). В остальных — вкладка «Текст».
- Скорость чата и анализа зависит от вашего железа: на CPU 7B-модель отвечает медленнее,
  с GPU (Ollama сам задействует CUDA/Metal) — комфортно.
- Для очень больших библиотек (десятки тысяч документов) имеет смысл перейти на pgvector —
  сейчас близость считается в памяти сервера, что оптимально для личного использования.
